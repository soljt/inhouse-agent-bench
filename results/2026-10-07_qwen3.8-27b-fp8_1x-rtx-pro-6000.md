## Reported by vLLM

| Metric | Value |
| --- | --- |
| Attention backend | FlashInfer (candidates: FlashInfer, Triton) |
| Weight loading | 184.0 s (about 170 MB/s from the global volume) |
| Model load total | 187.7 s, 28.51 GiB GPU memory |
| Available KV cache memory | 54.2 GiB |
| GPU KV cache size | 1,648,594 tokens |
| Max concurrency at 131,072 tokens/request | 12.58x |
| Startup, engine init to KV cache ready | about 4.7 min (15:39:04 to 15:43:46) |

Against the target load of 4 agents x 131k tokens (524,288 tokens), the KV cache
holds 3.1x that.

Derived from the above:

- **About 34.5 KiB per token** (54.2 GiB / 1,648,594 tokens), 8% above the 32 KiB
  FP8 estimate in our hardware comparison. vLLM's figure covers everything in
  the cache pool, likely including the linear-attention layers' per-sequence
  state, so it's the effective number to plan with.
- **GPU memory budget:** 0.92 x 97,887 MiB = 87.9 GiB, of which 28.5 GiB weights,
  54.2 GiB KV cache, and about 5.2 GiB left for activations, CUDA graphs and the
  vision encoder.

**Warning in log:** `Checkpoint does not provide a q scaling factor. Setting it to
k_scale.` The FP8 KV cache runs with default scales rather than calibrated ones,
which may cost some accuracy.
